Architecture Transformer

Module : Deep Learning Lecon 5/10 50 min Avance

Le paper "Attention Is All You Need"

En juin 2017, une equipe de chercheurs de Google Brain et Google Research, dirigee par Ashish Vaswani, a publie l'article "Attention Is All You Need", un des articles les plus influents de l'histoire du machine learning. Ce paper a introduit l'architecture Transformer, qui a revolutionne le traitement du langage naturel et, plus largement, tous les domaines du deep learning.

Auparavant, les modeles de sequence les plus performants utilisaient des reseaux recurents (RNN) et leurs variantes (LSTM, GRU). Ces architectures traitent les donnees sequentiellement, mot par mot, ce qui les rend lents a entrainer - impossibles a paralleleser sur les sequences longues. Le Transformer a elimine la recurrence et repose entierement sur un mecanisme d'attention, permettant un traitement massivement parallelisable.

Le contexte de publication est important : en 2017, les modeles de NLP etaient domines par les LSTM. L'architecture Seq2Seq avec attention etait l'etat de l'art pour la traduction automatique. Le paper a demontre que le Transformer surpasse ces approches non seulement en performance (scores BLEU), mais aussi en vitesse d'entrainement, ouvrant la voie aux grands modeles de langage.

Impact historique : Le Transformer est devenu l'architecture fondamentale de presque tous les grands modeles modernes : BERT, GPT-2/3/4, T5, PaLM, LLaMA, Mistral, et bien d'autres. Sans le Transformer, les LLMs tels que nous les connaissons n'existeraient pas. C'est probablement le paper le plus cite en deep learning depuis "Deep Residual Learning" (ResNet).

Mecanisme d'Attention

Le coeur du Transformer est le mecanisme d'auto-attention (self-attention). L'intuition est simple : pour chaque element d'une sequence, l'attention determine quels autres elements sont importants pour en comprendre le sens. En termes techniques, l'attention calcule une combinaison ponderee de toutes les valeurs de la sequence, ou les poids dependent de la similarite entre les elements.

Query, Key, Value

L'attention est definie par trois concepts fondamentaux :

  • Query (Q) : la question que pose chaque element. "De quoi est-ce que j'ai besoin ?"
  • Key (K) : l'etiquette de chaque element. "De quoi est-ce que je parle ?"
  • Value (V) : la valeur reelle de chaque element. "Ce que je contiens."

Chaque entree x est projetee dans trois espaces differents via des matrices de poids apprises : Q = xWQ, K = xWK, V = xWV. L'attention calcule ensuite la similarite entre chaque Q et chaque K, normalise les scores, et utilise ces poids pour combiner les V.

Formule d'Attention

Attention(Q, K, V) = softmax(QKT / sqrt(dk)) * V

Le calcul se fait en plusieurs etapes :

  1. Produit scalaire QKT : calcule la matrice de similarite (n x n) ou chaque element (i,j) mesure a quel point le token i "prete attention" au token j.
  2. Division par sqrt(dk) : normalise les scores pour eviter que les produits scalaires ne deviennent trop grands (surtout quand dk est grand), ce qui pourrait envoyer le softmax dans des zones de gradient tres petit.
  3. Softmax : convertit les scores en probabilités (chaque ligne somme a 1).
  4. Multiplication par V : chaque token est exprime comme une combinaison ponderee de tous les tokens, les poids etant determines par l'attention.

Exemple numerique

# Sequence de 3 tokens, dimension d_k = 4
# Tokens: ["Le", "chat", "dort"]

# Matrices apprises (simplifie)
Q = [[0.2, 0.8, 0.1, 0.5],   # Le
     [0.7, 0.3, 0.9, 0.2],   # chat
     [0.4, 0.6, 0.3, 0.7]]   # dort

K = [[0.1, 0.9, 0.4, 0.3],
     [0.8, 0.2, 0.7, 0.5],
     [0.3, 0.5, 0.6, 0.8]]

# QK^T (scores de similarite)
scores = Q @ K.T
# scores = [[0.72, 0.85, 0.89],
#           [0.94, 1.33, 1.16],
#           [0.81, 1.07, 1.14]]

# Division par sqrt(d_k) = sqrt(4) = 2
scores = scores / 2
# scores = [[0.36, 0.43, 0.45],
#           [0.47, 0.67, 0.58],
#           [0.41, 0.54, 0.57]]

# Softmax (par ligne)
import numpy as np
def softmax(x, axis=-1):
    e = np.exp(x - np.max(x, axis=axis, keepdims=True))
    return e / e.sum(axis=axis, keepdims=True)

attention_weights = softmax(scores)
# weights = [[0.31, 0.34, 0.35],
#            [0.29, 0.37, 0.34],
#            [0.30, 0.35, 0.35]]

# Multiplication par V
V = [[0.5, 0.1, 0.8, 0.3],
     [0.2, 0.7, 0.4, 0.6],
     [0.9, 0.3, 0.1, 0.5]]

output = attention_weights @ V
# Chaque token est maintenant une combinaison
# ponderee de tous les tokens de la sequence

Complexe O(n²)

La complexite en temps et en memoire de l'auto-attention est O(n²) ou n est la longueur de la sequence. Pour une sequence de 1000 tokens, la matrice d'attention fait 1000x1000 = 1 million d'elements. Pour GPT-4 avec des sequences de 128K tokens, c'est 16 milliards d'elements - un defi computationnel majeur. C'est pourquoi des optimisations comme Flash Attention ont ete developpees.

Multi-Head Attention

Plutot qu'une seule tete d'attention, le Transformer utilise plusieurs tetes d'attention en parallele. Chaque tete apprend a se concentrer sur des aspects differents de la sequence : une tete peut capturer les dependances syntaxiques, une autre les relations semantiques, une troisieme les references co-referentielles.

MultiHead(Q, K, V) = Concat(head1, ..., headh) * WO

Ou chaque tete est une attention independante :

headi = Attention(Q * WiQ, K * WiK, V * WiV)

Si le modele a une dimension dmodel = 512 et h = 8 tetes, chaque tete opere dans un espace de dimension dk = dmodel / h = 64. La complexite totale reste la meme qu'une seule attention, car les tetes sont plus petites. La projection finale WO (de dimension dmodel x dmodel) combine les sorties de toutes les tetes.

Pourquoi multi-head ? Une seule tete d'attention ne peut se concentrer que sur un seul "type de relation" a la fois. Avec 8 ou 16 tetes, le modele peut simultanement capturer differentes formes de dependances linguistiques. Les analyses d'attention montrent que certaines tetes se specialisent dans les articles, d'autres dans les adjectifs, d'autres encore dans les relations sujet-verbe.

Positional Encoding

L'auto-attention est invariante par permutation : elle traite la sequence comme un ensemble, sans notion d'ordre. Pourtant, l'ordre des mots est crucial dans le langage ("Le chat mange le poisson" vs "Le poisson mange le chat"). Le positional encoding injecte l'information de position dans le modele.

Encodage sinusoidal (Transformer original)

PE(pos, 2i) = sin(pos / 100002i/dmodel)
PE(pos, 2i+1) = cos(pos / 100002i/dmodel)

Pour chaque position pos et chaque dimension i, on utilise une fonction sinusoidale avec une frequence differente. Les positions sont encodees comme des vecteurs de dimension dmodel. Ces encodages sont ajoutes aux embeddings des tokens (pas concatenes). L'avantage de cette approche est qu'elle generalise a des sequences plus longues que celles vues pendant l'entrainement.

Positional Encoding appris

Dans cette variante, les encodages de position sont des parametres appris (une table de lookup). GPT etBERT utilisent cette approche. Elle est flexible mais ne generalise pas aux longueurs de sequence inconnues.

RoPE (Rotary Position Embeddings)

Utilise dans LLaMA, Mistral, et d'autres modeles modernes, RoPE encode les positions en tournant les vecteurs Q et K dans l'espace. Plutot que d'ajouter un encodage positionnel, RoPE applique une rotation dependant de la position. Le produit scalaire entre Q et K refleche alors naturellement la distance relative entre les positions, ce qui est une propriete tres desirable.

ALiBi (Attention with Linear Biases)

ALiBi ajoute un biais lineaire proportionnel a la distance entre les positions aux scores d'attention. Pas d'encodage de position ajoute aux embeddings. C'est simple, efficace, et generalise bien aux sequences longues. Utilise dans BLOOM et MPT.

Architecture Complete du Transformer

L'architecture originale du Transformer est un encodeur-decodeur. L'encodeur traite la sequence d'entree, le decodeur genere la sequence de sortie. Chaque bloc contient les memes sous-composants empiles.

Bloc d'Encodeur

  1. Multi-Head Self-Attention : chaque token peut "voir" tous les autres tokens de la sequence d'entree.
  2. Add & Norm : connexion residuelle (addition de l'entree et de la sortie) suivie d'une normalisation de couche (Layer Normalization).
  3. Feed-Forward Network : un reseau de neurones a deux couches (typiquement 4 * dmodel dans la couche cachee) avec une activation ReLU ou GELU.
  4. Add & Norm : autre connexion residuelle et LayerNorm.

Bloc de Decodeur

  1. Masked Multi-Head Self-Attention : comme l'auto-attention, mais avec un masque qui empeche chaque token de "voir" les tokens futurs. C'est essentiel pour l'entrainement autoregressif.
  2. Add & Norm
  3. Cross-Attention : les Q viennent du decodeur, les K et V viennent de l'encodeur. Permet au decodeur de "consulter" la sequence d'entree.
  4. Add & Norm
  5. Feed-Forward Network
  6. Add & Norm

Residual Connections

Les connexions residuelles (skip connections) sont fondamentales pour entrainer des reseaux profonds. Elles ajoutent l'entree d'un bloc a sa sortie : y = x + F(x). Cela permet aux gradients de circuler directement a travers les couches, evitant le vanishing gradient. Sans connexions residuelles, les Transformers profonds (24, 48, ou 96 couches) seraient impossibles a entrainer.

Layer Normalization

Le LayerNorm normalise les activations le long de la dimension des features pour chaque exemple individuellement. Contrairement au BatchNorm (qui normalise le long du batch), le LayerNorm est independant du batch et fonctionne bien pour les sequences de longueurs variables. La formule est : x' = (x - mean) / sqrt(var + eps) * gamma + beta, ou gamma et beta sont des parametres appris.

Variants : BERT, GPT, T5

L'architecture Transformer a donne naissance a trois grandes familles de modeles, chacune utilisant une partie differente de l'architecture originale.

BERT (Bidirectional Encoder Representations from Transformers)

BERT utilise uniquement l'encodeur du Transformer. Il est bidirectionnel : chaque token a acces a tous les autres tokens (passes et futurs). BERT est entraine avec deux objectifs : Masked Language Modeling (MLM, predire des mots masques) et Next Sentence Prediction (NSP, predire si deux phrases se suivent). BERT est idéal pour les taches de comprehension de texte : classification, extraction d'entites, question-reponse.

GPT (Generative Pre-trained Transformer)

GPT utilise uniquement le decodeur du Transformer. Il est autoregressif : chaque token ne peut voir que les tokens precedents (pas les futurs). GPT est entrainé pour predire le token suivant (Next Token Prediction). C'est l'architecture des grands modeles de langage : GPT-2, GPT-3, GPT-4, LLaMA, Mistral. La generation de texte se fait iterativement : on predit le token suivant, on l'ajoute a la sequence, et on repete.

T5 (Text-to-Text Transfer Transformer)

T5 utilise l'encodeur-decodeur complet. Toutes les taches de NLP sont reformulees comme des problemes texte-vers-texte : la traduction, la classification, le resume - tout prend du texte en entree et produit du texte en sortie. T5 a demontre que cette unification est tres flexible et performante.

Tableau comparatif

  • BERT : encodeur seul, bidirectionnel, compréhension, 110M-340M parametres
  • GPT : decodeur seul, autoregressif, generation, 117M-1800B parametres
  • T5 : encodeur-decodeur, flexibilite, texte-vers-texte, 60M-11B parametres

Flash Attention : optimisation de la memoire

Flash Attention, developpe par Tri Dao et al. (2022), est une implementation efficace de l'attention qui reduit drastiquement l'utilisation de la memoire GPU sans changer les resultats mathematiques. C'est une optimisation systeme critique pour entrainer et inferer de grands modeles.

Le probleme fondamental est que l'attention standard stocke la matrice n x n dans la memoire GPU (HBM - High Bandwidth Memory), ce qui est couteux en memoire et en temps d'acces. Flash Attention utilise le tiling : il decoupe les matrices Q, K, V en petits blocs qui tiennent dans la memoire cache (SRAM, beaucoup plus rapide) du GPU.

Plutot que de calculer la matrice d'attention complete (O(n²) en memoire), Flash Attention calcule l'attention bloc par bloc en utilisant la formule de softmax en ligne (online softmax). A chaque etape, il met a jour les sorties avec les nouveaux blocs sans jamais stocker la matrice complete. La complexite en memoire passe de O(n²) a O(n), et le temps d'execution est reduit de 2x a 4x grace a la reduction des lectures/ecritures en memoire globale.

Flash Attention 2 et 3 : Flash Attention 2 ameliore le parallelisme sur les sequences, et Flash Attention 3 (2024) exploite les instructions specifiques des GPU Hopper (H100) comme TMA et les asynchronismes pour atteindre des performances proches du pic theorique du GPU. C'est desormais un composant standard dans tous les frameworks d'entrainement de LLMs.

Code : Implementation PyTorch simplifiee

import torch
import torch.nn as nn
import torch.nn.functional as F
import math

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model, n_heads):
        super().__init__()
        assert d_model % n_heads == 0
        self.d_k = d_model // n_heads
        self.n_heads = n_heads

        self.W_q = nn.Linear(d_model, d_model)
        self.W_k = nn.Linear(d_model, d_model)
        self.W_v = nn.Linear(d_model, d_model)
        self.W_o = nn.Linear(d_model, d_model)

    def forward(self, x, mask=None):
        batch_size, seq_len, _ = x.size()

        # Projeter dans Q, K, V et separer les tetes
        Q = self.W_q(x).view(batch_size, seq_len, self.n_heads, self.d_k).transpose(1, 2)
        K = self.W_k(x).view(batch_size, seq_len, self.n_heads, self.d_k).transpose(1, 2)
        V = self.W_v(x).view(batch_size, seq_len, self.n_heads, self.d_k).transpose(1, 2)

        # Attention
        scores = torch.matmul(Q, K.transpose(-2, -1)) / math.sqrt(self.d_k)
        if mask is not None:
            scores = scores.masked_fill(mask == 0, float('-inf'))
        attention = F.softmax(scores, dim=-1)
        context = torch.matmul(attention, V)

        # Concatener les tetes et projeter
        context = context.transpose(1, 2).contiguous().view(batch_size, seq_len, -1)
        return self.W_o(context)


class TransformerBlock(nn.Module):
    def __init__(self, d_model, n_heads, d_ff, dropout=0.1):
        super().__init__()
        self.attention = MultiHeadAttention(d_model, n_heads)
        self.norm1 = nn.LayerNorm(d_model)
        self.norm2 = nn.LayerNorm(d_model)
        self.ff = nn.Sequential(
            nn.Linear(d_model, d_ff),
            nn.GELU(),
            nn.Linear(d_ff, d_model),
            nn.Dropout(dropout)
        )
        self.dropout = nn.Dropout(dropout)

    def forward(self, x, mask=None):
        # Self-attention avec connexion residuelle
        attn_out = self.attention(x, mask)
        x = self.norm1(x + self.dropout(attn_out))
        # Feed-forward avec connexion residuelle
        ff_out = self.ff(x)
        x = self.norm2(x + ff_out)
        return x


class PositionalEncoding(nn.Module):
    def __init__(self, d_model, max_len=5000):
        super().__init__()
        pe = torch.zeros(max_len, d_model)
        position = torch.arange(0, max_len, dtype=torch.float).unsqueeze(1)
        div_term = torch.exp(torch.arange(0, d_model, 2).float() * (-math.log(10000.0) / d_model))
        pe[:, 0::2] = torch.sin(position * div_term)
        pe[:, 1::2] = torch.cos(position * div_term)
        self.register_buffer('pe', pe.unsqueeze(0))

    def forward(self, x):
        return x + self.pe[:, :x.size(1)]


class SimpleTransformer(nn.Module):
    def __init__(self, vocab_size, d_model=256, n_heads=8, n_layers=4,
                 d_ff=1024, max_len=512, num_classes=10):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, d_model)
        self.pos_enc = PositionalEncoding(d_model, max_len)
        self.layers = nn.ModuleList([
            TransformerBlock(d_model, n_heads, d_ff)
            for _ in range(n_layers)
        ])
        self.classifier = nn.Linear(d_model, num_classes)

    def forward(self, x, mask=None):
        x = self.embedding(x) * math.sqrt(256)
        x = self.pos_enc(x)
        for layer in self.layers:
            x = layer(x, mask)
        # Pooling: moyenne sur les positions
        x = x.mean(dim=1)
        return self.classifier(x)

# Exemple d'utilisation
model = SimpleTransformer(vocab_size=30000, num_classes=5)
x = torch.randint(0, 30000, (2, 128))  # batch de 2, sequence de 128
output = model(x)
print(f"Output shape: {output.shape}")  # [2, 5]
print(f"Parametres: {sum(p.numel() for p in model.parameters()):,}")

Questions d'entretien frequentes

Q1 : Pourquoi diviser par sqrt(d_k) dans la formule d'attention ?

Sans cette normalisation, les produits scalaires QKT croissent en magnitude avec la dimension dk. Pour des valeurs grandes, le softmax retourne des distributions tres concentrees (proches de one-hot), ce qui conduit a des gradients tres petits (vanishing gradient). La division par sqrt(dk) maintient les valeurs d'entree du softmax dans un range raisonnable, assurant des gradients sains et un entrainement stable.

Q2 : Quelle est la difference entre self-attention et cross-attention ?

En self-attention, Q, K et V proviennent tous de la meme sequence : les tokens de la sequence se comparent entre eux. En cross-attention, Q provient d'une sequence (le decodeur) et K/V d'une autre (l'encodeur). Le cross-attention permet au decodeur de "consulter" l'information de la sequence d'entree. C'est le mecanisme qui connecte l'encodeur et le decodeur dans l'architecture Seq2Seq.

Q3 : Pourquoi le Transformer est-il plus rapide a entrainer qu'un LSTM ?

Deux raisons principales : 1) Parallelisation : l'auto-attention peut traiter tous les tokens simultanement (operation de matrice), tandis que le LSTM traite les tokens sequentiellement. Sur GPU, l'attention est 10x-100x plus rapide. 2) Distance dependancy : dans un LSTM, l'information d'un token a l'autre bout de la sequence doit traverser toutes les couches intermediaires, ce qui affaiblit le signal. En self-attention, chaque token a un acces direct (O(1)) a tous les autres tokens.

Q4 : Comment Flash Attention ameliore-t-il les performances sans changer les resultats ?

Flash Attention est une reimplementation de l'attention identique mathematiquement mais optimisee systemiquement. Il utilise le tiling pour travailler avec des blocs qui tiennent dans la memoire cache (SRAM) du GPU, plutot que d'aller chercher les donnees en memoire globale (HBM). Il calcule le softmax en ligne pour eviter de stocker la matrice d'attention complete. Le resultat est identique, mais le temps d'execution est reduit de 2x-4x et la memoire utilisee passe de O(n²) a O(n).

Q5 : Pourquoi le masked self-attention est-il necessaire dans le decodeur ?

Le mask empeche chaque position de "voir" les positions futures. Sans masque, le modele pourrait simplement recopier le token suivant sans rien apprendre. Pendant l'entrainement, on fournit toute la sequence de sortie en meme temps (teacher forcing), et le masque garantit que chaque prediction ne depend que des tokens precedents. Pendant l'inférence, les tokens sont generes un par un, donc le masque est naturellement respecte. C'est ce qui rend le modele autoregressif.
